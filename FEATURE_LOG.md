# Feature Log

Chronological record of every request made and what was built/changed in response, across the whole conversation that produced this project. Ordered oldest → newest. Use this to understand *why* something exists, or whether an earlier decision was later changed.

1. **Initial build request.** Portfolio site for a designer/artist, minimal/clean/not-colourful style. Built as a single HTML file: hero, work grid, about, contact sections. Dark-neutral palette originally light-toned ("paper"/"ink" tokens named for a light theme).
2. **"Make it interactive."** Added: click-to-filter work grid (initially by medium categories), click-to-expand lightbox with keyboard/arrow navigation.
3. **Clarified the work is 3D and 2D images**, not painting/traditional art. Rewrote all copy, tool tags, and filter categories (Oil/Acrylic/Mixed Media → 3D/2D, then later 3D render/2D illustration) to match.
4. **Uploaded a dark diagonal-line background image**, asked to replace the white background and make it interactive on scroll. Flipped the entire theme to dark (this is when `--paper`/`--ink` values inverted but names were kept). Added scroll+mouse-driven parallax on the background layer.
5. **"Add a particle effect when clicking 3D or 2D."** Built the canvas-based particle burst system, initially only wired to the 3D/2D filter buttons.
6. **Added name/details**: real name (Dineth Meehitiya), bio, contact links (2 emails at the time, ArtStation, YouTube, Instagram), location (Melbourne, VIC), real tool list (Photoshop, Maya, ZBrush, Unity, Unreal Engine, Substance Painter, Blender).
7. **Removed the large hero headline** ("Built in three dimensions, felt in two.") — decided it wasn't needed.
8. **Replaced the background image** with a procedurally generated (Python/PIL) dark ambient image with a soft glow + film grain, specifically to be "simple" and "high quality" without using a stock photo (avoids licensing questions entirely).
9. **Uploaded a custom font (`Retron2000.ttf`)**, asked to replace *all* fonts site-wide. Embedded via `@font-face` base64, applied globally.
10. **Removed the "Work / About / Contact" text nav** from the header (redundant at the time).
11. **Particle effect extended to "All"**, and its colour changed to **dark gold** — but this was done incorrectly at first (applied gold to 3D/Concept/Graphic too). **Corrected**: gold is "All" only, everything else reverted to white/ivory. (See Design System doc — this is a firm rule now.)
12. Shortened the contact heading from "Available for commissions and gallery inquiries." to just "Available for commissions."
13. **Moved the 3 social links (ArtStation/YouTube/Instagram) to sit directly under the "Available for commissions" heading**, separated visually from the email addresses below them.
14. **Added a "Projects" category** (initially empty, no content yet) alongside 3D/2D, with the same particle effect wired up.
15. **Moved bio + portrait image to the top of the page**, removed the (now redundant) old intro paragraph.
16. **Removed two bio paragraphs** ("My practice moves between mediums..." and "Based in Melbourne, VIC. I take on a small number...") leaving just the single lead paragraph.
17. **Added top-right icon links**: YouTube, ArtStation, Instagram as inline SVG icons in the header, replacing/alongside the text nav removed earlier.
18. Person reported the icon links "aren't working" — investigated; HTML/hrefs confirmed correct. Likely cause: sandboxed in-chat file preview blocking `target="_blank"` navigation, not a real bug. **Not independently re-confirmed working** by the person after being told to test in a real browser tab — worth re-checking if raised again.
19. **Added LinkedIn** — both as a 4th top-right icon and as a text link in the contact section.
20. Removed "— Est. 2016" from the "3D & 2D Artist" label.
21. **Added a full 3D sub-filter system**: clicking "3D" reveals a second row (All 3D / 3D Modelling / 3D Printing / 3D Animation). Retagged existing pieces into these sub-categories, added one placeholder piece ("Cast Form") to fill the otherwise-empty Printing sub-category.
22. **Replaced "Concept Art" and "Graphic Design" as top-level filters with a single "2D" top-level filter**, given the same sub-filter treatment as 3D (All 2D / Concept Art / Character Art / Graphic Design — Character Art added as new). Retagged existing pieces accordingly (one piece relabelled from Concept Art to Character Art to populate the new sub-category).
23. **Uploaded 3 real poster pieces** (Wings & Waves, Spectral Emergence, Monarch — Butterfly Effect) and added them as real Graphic Design pieces, replacing the two placeholder pieces that existed before.
24. **Removed the grayscale-by-default / colour-on-hover effect** on all images — everything shows full colour all the time now.
25. **Uploaded 2 framed mockup images for Wings & Waves**, asked to add them as additional views *without changing the front/default image*. Built the gallery-thumbnail pattern (see Design System doc) to support this — this was the first use of the `data-gallery`/`gallery` field.
26. **Repeated the same gallery pattern for Monarch — Butterfly Effect** (2 mockups) and **Spectral Emergence** (2 mockups).

29. Person asked again whether the top-right links work — re-explained the likely sandboxed-preview cause, no code change made (nothing found to fix).

33. **Added a real YouTube video** (as a playable embedded piece, not just a thumbnail/link) under Projects → Game. Built the video-piece pattern: YouTube-hosted thumbnail with CSS play-button overlay in the grid, real `<iframe>` embed in the lightbox/detail view, playback stopped on close.
34. **Repeated the video pattern for Projects → Animation** with a second real YouTube video.
35. Person asked about pricing (a "$30 package") to "do better" — researched Anthropic's current plan pricing to answer accurately, but the person then said to set pricing aside and focus on the build. No code changes.
36. **The big rebuild request.** Person shared two wireframe images and a detailed explanation of a much more ambitious vision: a central rotating 3D "icon in a glass/reflective orb" as the homepage centerpiece, doubling as a toggle to a separate "About Me" page; three category labels (3D Art / 2D Art / Projects) branching into sub-category lists on hover; clicking a category/sub-category leads to its own page of work (reusing the particle effect); clicking a work item leads to a dedicated page explaining it; full back-navigation throughout; the existing "Available for commissions" section reachable by scrolling down on the home page. Explicitly asked to **keep the existing colour palette, typography, and particle effect** (experimentation with the effect allowed but optional), and to use placeholder images where a real "icon" asset doesn't exist yet.
    - Clarified two open decisions before building: **(a)** orb fidelity — chose **true 3D WebGL glass sphere (Three.js)** over a cheaper CSS/SVG stylized approximation; **(b)** Projects sub-items — chose **both** a year filter *and* keeping the existing Animation/Game type tags (not replacing one with the other).
    - Built **`portfolio_v2.html`**: extracted all 15 real work pieces (with their full images, galleries, and video IDs) out of `portfolio.html` into a single `WORK_DATA` JS array so nothing had to be re-uploaded; reused the header, contact section, about content, fonts, background, and particle system verbatim; built a new four-screen "fake SPA" (Home / About / Category / Detail) with a Three.js glass-sphere orb (procedural environment map, auto-rotation, mouse-tilt, click/keyboard-activatable, navigates to About) and hover-expanding category labels on the home screen. Category and Detail screens are fully dynamic, rendered from `WORK_DATA` at runtime rather than hand-written per piece. Projects category got the dual year/type-tag filtering as agreed.
    - Flagged as first-pass/known-rough: the orb's visual quality (lighting/environment/icon integration), lack of real per-piece descriptions on detail pages, placeholder titles on two pieces, no mobile-specific tuning yet, no browser-history integration.
37. **This documentation request** — asked for a `CLAUDE.md` and supporting docs capturing all of the above so work can continue in a fresh Claude Code repo. Produced this file, `CLAUDE.md`, `docs/DESIGN_SYSTEM.md`, and `data/work-data.json` (the real content data extracted to a standalone, reusable file).
