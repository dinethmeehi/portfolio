## Design system

See `docs/DESIGN_SYSTEM.md` for full detail. Summary:

- **Theme:** dark, moody, minimal. Not colourful — the person was explicit about this early on ("minimal, clean and not too colourful").
- **Font:** a single custom uploaded font, **Retron2000** (`Retron2000.ttf`, embedded as a `@font-face` base64 `data:font/ttf` URI), used for **everything** — headings, body, labels, buttons. This was an explicit request ("change all the font into a new font"). There is no fallback stack beyond generic `sans-serif`.
- **Colour tokens (CSS custom properties):**
  ```css
  --paper:#0A0A0B;   /* base dark background */
  --ink:#F2F0EA;     /* primary text, off-white */
  --muted:#A6A199;   /* secondary text */
  --accent:#C9BFA0;  /* soft warm silver/gold accent */
  --line:rgba(255,255,255,0.14);
  --card:rgba(255,255,255,0.05);
  ```
- **Background:** a looping VFX video clip (person-supplied, `Background vfx/45947-447087546_medium.mp4`), embedded as a base64 `data:video/mp4` source on a fixed, full-viewport `<video autoplay muted loop playsinline>` layer behind everything (`#bg-layer`). The original procedurally generated (Python/PIL) dark ambient JPEG — soft off-white glow + film grain — is kept as the video's `poster`. It has scroll-driven and mouse-driven parallax (rotates, scales, and brightens as you scroll; drifts slightly with the cursor), plus a CSS `blur(2.5px)` and darkened brightness/overlay so body text stays legible over the busier moving footage. Video is explicitly paused and parallax skipped under `prefers-reduced-motion`.
- **Signature interaction — particle burst:** clicking any filter/category button throws a small canvas-based burst of outlined shapes (squares, triangles, lines, cubes) from the cursor position. Shape language is tied to category:
  - **3D** → cubes/triangles
  - **2D** → mixed squares/triangles/lines
  - **Projects** → cubes/squares
  - **All** → mixed shapes (same white/ivory palette as everything else — see below).
  - **The gold/brown "All" accent (`120,88,32` / `184,140,64`) has been removed** as part of the Generative Wireframe visual direction (see below) — the person explicitly asked for the whole generative-effects layer (particles, wireframe, connections) to be strictly monochrome, no neon/gold/cyberpunk colour anywhere. `makeParticle()` now always uses the plain white/ivory pair (`242,240,234` / `201,191,160`) regardless of mode. **This supersedes the old "gold-only-on-All, don't reintroduce elsewhere" rule** — there is no gold left to reintroduce. The `--accent` CSS variable (`#C9BFA0`, used for hover/active UI states like `.cat-panel.active`, `.orb-info-cta`, contact-link hover) was deliberately left untouched — it's a subtle, already-desaturated sitewide UI tone, not the "neon cyberpunk" colour the person was reacting to, and touching it wasn't part of what was asked.
- **Mouse-trail dust (Step 08, FEATURE_LOG #62):** a second, visually distinct particle pool (`dust`, plain small filled circles via `drawDust()` — not the burst system's outlined shapes) sharing the same `#particle-canvas`/`stepParticles()` loop as the click-burst above. A sitewide `pointermove` listener spawns 1–2 dots whenever the cursor moves ≥8px from its last spawn point (distance-throttled, not per-event), always plain white/ivory (never gold), capped at a 140-dot pool. Only attached under `!reduceMotion`. Deliberately subtle per the person's explicit "not a glowing cursor trail" — low opacity, small size, slow drift. As of the Generative Wireframe pass, `stepParticles()` also draws thin, distance-faded, capped (18/frame, 90px range) connecting lines between nearby dust motes — see below.
- All motion respects `prefers-reduced-motion: reduce`.

- **Generative Wireframe Background** (added on top of the v1/v2 visual system, at the person's request for a "black-and-white experimental digital editorial" direction — explicitly *not* a rebuild, everything above/below this bullet stayed intact): a new `#wireframe-canvas` layer (`position:fixed; inset:0; z-index:-1; pointer-events:none`), declared in the DOM right after `#bg-overlay` so it paints above the video/overlay but — because it shares their negative z-index — stays behind every real page element (content, orbs, header, nav) without needing to touch the existing positive-z-index stacking (`#particle-canvas` stays at `z-index:60`, still rendering *above* content for the burst/dust cursor effects, unchanged). Implemented as a single `WireframeSystem` IIFE (`portfolio_v2.html`, just before the "THREE.JS ORB CAROUSEL" block, since orb hover/click handlers call into it):
  - **Procedural line structures, keyed by `mode`** (`home` / `2d` / `3d` / `projects` / `about`, matching `state.category`/screen names 1:1) — each mode is a different *arrangement* of the same primitives (corner brackets, fragmented/partially-open rectangles, isometric boxes, converging perspective lines), not a different visual system: `home` is sparse with a clean centre for the orb diagram; `2d` is a loose editorial grid; `3d` uses perspective lines converging toward an interior vanishing point plus small isometric boxes; `projects` is busier/fragmented (many short disconnected segments); `about` is the cleanest, archive-document style (two long hairlines + one mostly-open outer frame). `WireframeSystem.setMode(...)` is called from `goHome()`, `goAbout()`, and `showCategory(cat, ...)` — regenerates the line set only when the mode actually changes.
  - **Interactive**: lines track the pointer (each endpoint nudges a few px toward/away from the cursor within a 180px radius, decaying smoothly via lerp when the cursor moves away — not a screen-wide shake), brighten slightly near an active "focus" point, drift subtly on their own (per-line sine phase), and shift a small amount with scroll position and mouse-relative parallax (depth-weighted per line, echoing the existing `#bg-layer` parallax but far more subtle).
  - **Ambient node network**: a separate small pool of drifting points (16/28/42 on mobile/tablet/desktop) draws thin, distance-capped connecting lines between nearby nodes each frame (max 14/24/36 connections) — the "generative network" look, as a calm background counterpart to the dust-particle connections above.
  - **Orb integration**: orb hotspot `pointerenter`/`pointerleave` call `WireframeSystem.focus(x, y)` / `unfocus()` (brightens nearby lines toward the hovered orb); the click handlers (About + all three category orbs) call `WireframeSystem.convergeAt(x, y)` alongside the existing `burstParticles(...)` call, pulling nearby lines toward the click point for a beat — additive, layered on top of the existing `navigateWithSplit()`/`splitOrbEffect()` animation, which is untouched.
  - **Reduced motion**: under `prefers-reduced-motion`, no pointermove/scroll listeners are attached and no rAF loop runs at all — `drawStatic()` renders the current line set once and stops, matching the rest of the site's reduced-motion pattern (static rather than removed).
  - **Performance**: devicePixelRatio capped at 2 (same pattern as the Three.js renderer), line/node counts tiered by viewport width, all mouse-position math deferred into the rAF draw loop rather than done per raw `pointermove` event, `document.hidden` checked each frame to skip drawing when the tab isn't visible.
  - **Background video**: `#bg-layer`'s `saturate(...)` was lowered from `1.05` to `0.3` (both in the CSS rule and the JS `updateBackground()` template string that overwrites it on scroll/mousemove) to pull the atmospheric background video toward monochrome, per the person's explicit ask — blur/brightness/parallax behaviour is otherwise unchanged.

## v2 architecture (`portfolio_v2.html`)

Single-file "fake SPA" — no routing library, no build step. Four full-screen views toggled via a `.screen` / `.screen.active` class, all living in one `<main id="app">`, plus one extra full-viewport layer that sits in front of all of them on load:

0. **`#cover-screen`** — an intro/splash layer (`z-index:300`, first element in `<body>`, not part of the `.screen` system, solid `var(--paper)` background) showing a "DM" mark built as **inline SVG** — pill/capsule outlines with tick-mark stubs, two nested-square pairs, two overlapping-triangle pairs, two horizontal connector bars, and a `<text>` wordmark in Retron2000 (bold system text, not a hand-traced copy of the person's actual logotype file — a deliberate approximation) — plus a "Click to enter" hint. This replaced the earlier flat-PNG-with-transparent-cutout version (see `docs/FEATURE_LOG.md` #47) specifically so the decorative shapes could be individual, independently animatable elements. Clicking it (or `Enter`/`Space`) now runs a **two-phase exit**: each `.cover-shape` gets a `--dx/--dy/--dr`-driven scatter (translate+rotate+fade, 0.5s, via a `.cover-mark.scattering .cover-shape` rule) for ~520ms, *then* the original `cover-zoom` class (scale up + fade over 0.85s) plays — and, as of Step 02 (see FEATURE_LOG #48), the start of that zoom also calls `triggerOrbIntro()` so the home screen's orbs are already flying into place underneath as the cover fades — and once the transition finishes a `cover-hidden` class (`display:none`) removes the screen for the rest of the session. The two phases are sequenced with an explicit `setTimeout`, not `transitionend` bubbling — `transitionend` bubbles from descendants, so listening on `#cover-screen` itself while shape-transitions were still running would fire early. No persistence (localStorage/sessionStorage) — it shows on every full page load, not just the first visit. Skips the scatter phase entirely under `prefers-reduced-motion` (goes straight to the zoom-out step, same as before). This is **Step 01–10, the full 10-step plan** (see FEATURE_LOG #47) — all ten steps have now been implemented, though a broader sitewide editorial typography pass beyond the Step 09 scramble effect hasn't been attempted, and Step 10's mobile pass fixed real bugs it found rather than doing an exhaustive device audit (see FEATURE_LOG #64 and the Known Gaps note below). `#screen-detail` (the individual project page) also hasn't had an editorial pass yet — flagged as a likely candidate whenever this continues.
1. **`#screen-home`** — landing view, a single `<canvas id="orb-canvas">` (**Three.js r128**) rendering **four orbs laid out along a fixed "C" curve** (see FEATURE_LOG #51, repositioned again in #53, #54, then #65 for spacing/headroom — top-right smallest, sweeping left through two mid-sized points, down to **About Me at bottom-right, the largest** — `ABOUT_DEF`/`about`, `{x:1.6, y:-1.6, z:0.6, radius:1.5}`), plus the three category orbs (2D Art / 3D Art / Projects) permanently occupying the other three points. **There is no longer any rotation/selection mechanic** (removed in FEATURE_LOG #56 — see below) — each category always sits at the same point on the curve, and clicking any of the four orbs navigates straight there.
   - **Every orb** = a glass `MeshPhysicalMaterial` sphere (`clearcoat`, plain `opacity`-based translucency — **not** `transmission`, see below) plus a same-radius **wireframe** `SphereGeometry` shell drawn on top, plus a placeholder photo (`PlaneGeometry`, a rectangle not a circle) inside every orb. `scene.environment` is still the `#bg-layer` video texture (procedural gradient fallback under `prefers-reduced-motion`), applied to all four glass spheres automatically. Every orb also **floats gently up/down** (`group.position.y = baseY + sin(t * floatSpeed + floatPhase) * 0.09`, randomised speed/phase per orb so they don't bob in sync) on top of its own slow idle spin.
   - **Glass material uses `transmission:0` + `opacity:0.16`, not true `transmission:1.0`** — the earlier physically-based transmission gave truer refraction, but three.js implements it via a scene-background-capture render pass, and with the icon plane sitting just inside the shell, that pass doubled/tore the icon photo (visible as a diagonal seam splitting the image, worse at some rotation angles than others — the person caught and screenshotted it on multiple orbs). Plain alpha-blended opacity avoids that capture pass entirely; `clearcoat` + `envMapIntensity` still give the shell a reflective sheen from the background video. If a truer glass look is revisited later, this double-render risk is *why* — don't reach for `transmission` again without a plan for keeping "things inside the glass" clean.
   - **Wireframe material**: plain **white** (`0xF2F0EA`), dim (`opacity:0.3`), no vertex colours — this replaced an earlier per-vertex "Y2k holographic" colour sweep the person found too dim/not visible enough in practice; plain white read more clearly. (An even earlier attempt used a licensed stock photo texture via additive blending, also not visible enough — see `docs/FEATURE_LOG.md` for the full history. `Orbs/orb-texture-900.jpg` is unused now; only the wireframe remains.)
   - **Glow + ambient dust**: every orb also carries a `THREE.Sprite` glow halo (`makeGlowSprite`, a soft radial-gradient `CanvasTexture` reused for this and the dust below, additive-blended so it only ever brightens, never darkens) sized ~2.7× the orb's radius and added as a group child, so it automatically inherits that orb's position/scale. A single scene-wide `dustField` (`THREE.Points`, ~160 specks scattered through the visible volume, same glow texture, additive) drifts on a very slow independent rotation for ambient atmosphere. Both are purely decorative additions to the orb diagram only — the page background (`#bg-layer` video) is untouched by this.
   - **Fly-in entrance (Step 02, see FEATURE_LOG #48)**: every orb has an `.intro = {startX, startY, startZ, startScale, delay, duration}` descriptor — About Me spawns well above its resting spot at a fraction of its scale, each category orb spawns even higher/smaller with a randomised, staggered delay (`180 + i*160 + random`) so the three don't land in lockstep or symmetrically. `animate()` always writes `group.position`/`group.scale` now (previously this only happened inside the `if(!reduceMotion)` branch, which meant under reduced motion the category orbs never got positioned at all and would've sat stacked at the origin — fixed as part of this same change), blending via a cubic-ease `introProgress()` from the spawn state to the orb's normal live target (About's float sine, each category orb's slot-easing) — once progress reaches 1 this is identical to the pre-Step-02 behaviour, so the resting diagram itself is unchanged. `triggerOrbIntro()` (shared top-level state next to `reduceMotion`, since the cover-screen and orb code are separate IIFEs in the same `<script>` block) is called from the cover screen's `zoomOut()`, not on click itself — so orbs start arriving right as the existing zoom-fade begins. **As of Step 09 (FEATURE_LOG #63), `triggerOrbIntro()` also runs `scrambleText()` on all four `.orb-slot-label` elements** — a ~600ms scramble-to-real-text decode animation (random chars from `ABCDEFGHIJKLMNOPQRSTUVWXYZ0123456789/#_`, revealed left-to-right, spaces never scrambled), matching the person's typography reference. Deliberately scoped to *only* these four home-screen labels via the `.orb-diagram .orb-slot-label` selector — nothing on the category or detail screens gets this effect. Colour is untouched (`scrambleText` only rewrites `textContent`), so it stays inside the existing `--muted`/`--accent` palette rather than introducing a new one.
